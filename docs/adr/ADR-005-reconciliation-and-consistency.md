# ADR-005 — Reconciliation and consistency model

**Status:** Accepted<br>
**Decision owner:** Project maintainer<br>
**Review gate:** Must be Accepted before production coding

## Context

Jellyfin events may be broad, duplicated, generated by the plugin’s own writes, or emitted in large bursts. Multi-operation plans are not transactional.

## Decision

1. Events mark eligible items dirty; event handlers do not directly mutate Jellyfin state.
2. A deduplicating in-memory dirty set coalesces repeated events.
3. One serialized coordinator owns all synchronization mutations.
4. The planner computes complete desired state; it does not blindly translate events into opposite actions.
5. Self-generated events are tolerated through idempotence.
6. Normal activity is near-real-time.
7. Large scans/event storms degrade to broader Full Reconcile rather than unbounded queue growth.
8. A bulk reconciliation calculates its complete plan before writing. If planned
   Authoritative removals exceed the configured destructive safety limit, it
   applies no mutations and waits for administrator preview and confirmation.
   The default limit is more than 25 unique affected items across the run or
   more than 20 percent of one group's currently observed target assignments
   when that group has at least 10 assignments.
9. The consistency model is eventual.
10. On item mutation failure:
   - keep partial state;
   - stop remaining operations for that item;
   - do not rollback;
   - defer retry until Full Reconcile.
11. Full Reconcile continues after individual item failures and reports a summary.
12. Jellyfin/plugin startup queues one Full Reconcile when at least one
    continuous mapping is enabled. The request waits for a settling delay,
    coalesces with another pending bulk request, uses the serialized coordinator,
    and remains subject to the destructive circuit breaker.
13. The startup delay is administrator-configurable from 0 through 60 minutes
    and defaults to 5 minutes. Zero means as soon as Jellyfin is ready, not during
    plugin construction. If a library scan or event storm remains active when
    the delay expires, execution waits until the activity becomes quiet.
14. Failed-item quarantine is in memory. A restart may clear it, after which a
    later event or the startup Full Reconcile may retry the item.

## Consequences

- Runtime recursion does not become an infinite write loop.
- Missed events and partial writes are repairable.
- A failed item may remain temporarily inconsistent.
- A bulk run paused by the destructive circuit breaker remains inconsistent until
  an administrator approves it or later state produces a safe plan.
- Full Reconcile is a required operational feature, not an optional optimization.
- Drift accumulated while Jellyfin or the plugin was offline is repaired after
  startup without waiting for the next scheduled run.
- No transaction or rollback framework is required.

## Required examples

```text
Plugin adds Animation membership.
Jellyfin emits collection-added event.
Item queues again.
Second plan has zero delta.
```

```text
Operation 1 succeeds.
Operation 2 fails.
Operation 1 remains.
Item waits for Full Reconcile.
```

```text
One item produces many duplicate events during a scan.
The dirty set retains one item GUID.
If the event burst crosses the implementation threshold, fine-grained queue
growth stops and one broader Full Reconcile is requested.
```
